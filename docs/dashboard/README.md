# Accuracy dashboard

The public page for epic #61: per-detector precision, recall, and corpus evidence from the last full public
corpus run. Every number comes from `data.json`, which is generated from committed files and checked by CI.

| File | What it is |
| --- | --- |
| `index.html` | The page. Static HTML plus the data it reads. |
| `style.css` | One stylesheet, light and dark schemes, no web fonts or external assets. |
| `dashboard.js` | One classic script. Reads `data.json` and renders the tables, definitions, and limitations. |
| `data.json` | Generated by `tools/build-dashboard-data.ts`. Never edit it by hand. |

No framework, no CDN, and no network request other than `data.json` from this folder.

## Viewing it

Serve this folder and open it in a browser:

```bash
python3 -m http.server 8000 --directory docs/dashboard
# then open http://localhost:8000/
```

Or open the published page: <https://arminazimi.github.io/evergreen/dashboard/>.

Opening `index.html` straight from disk shows a message instead of numbers. Browsers refuse to let a page
loaded from `file://` read `data.json`, and that is a browser rule, not a page bug. Inlining the data into the
HTML is not an option: `data.json` is the committed file CI checks for drift, and a second copy would let the
page and the file disagree.

## Regenerating the data

```bash
npm run build:dashboard    # writes data.json
npm run check:dashboard    # fails if data.json is out of date
```

The build reads `benchmarks/thresholds.json` and `benchmarks/public-repositories.json`, never the clock or the
network. Its reference day is the date of the last full run, so the committed file does not change on its own.

## What the page shows

- The run metadata: date, commit, repositories, findings, and scan time. Scan time reads "not measured" because
  no committed file records it.
- One table for the ten detectors: configured level, earned level, precision, recall, true and false positives,
  and false negatives, plus the three evidence counts from decision 0013. A missing number reads
  "not measured", never 0 or 1.
- Where a configured level is higher than the earned level, the row is marked "above the counted evidence, kept
  by decision 0013".
- Every metric header links to its definition on the page and to its source file on GitHub.
- Every limitation in `data.json`, with the first one also written into the HTML so it reads without JavaScript.

There are no trend charts: one run is recorded, so there is no trend to draw.
