# Node corpus at 200 repositories

Selection for the 122 repositories added on 2026-11-07 (`benchmarks/public-repositories/node/0353` to `0474`) was fixed before Evergreen ran on them, following [decision 0030](../../decisions/0030-corpus-selection-and-200-target.md).

- **Discovery:** GitHub repository search on 2026-11-07 for `language:JavaScript` and `language:TypeScript`, 100–500 stars, `pushed:>=2024-11-07`, not a fork or archive, size under 50,000 KB, sorted by stars descending; the first 500 results of each (of 11,466 and 15,349) were exported, 1,000 distinct repositories. A code-search pass for `filename:package.json` first returned only 79 repositories with the manifest at the root, so the recorded source is the repository search; language alone was not treated as eligibility, and every repository was checked for a supported input at the root.
- **Eligibility:** public, not archived or a mirror, GitHub size at most 50,000 KB, a default-branch commit on or after 2024-11-07, a complete tree, an OSI-approved SPDX license with a license file in the tree, and a supported node input (`package.json`, `package-lock.json`, `pnpm-lock.yaml`, or `yarn.lock`) at the root. 807 of the 1,000 had a root input; 591 of those passed every check. The rest failed on a missing or non-OSI license (185) or activity (39).
- **Order:** the candidate finder inspected the first 300 candidates in profile order (`package.json`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`) by size band (at most 5,000 KB, then larger), sorted by lowercase `owner/name` and walked round-robin: 212 were eligible and one (`d3/d3-interpolate`) was already in the corpus. The first 122 eligible repositories not already reviewed were kept (57 `package.json`-first small and 63 medium, one `pnpm-lock.yaml`-first, one `yarn.lock`-first). Each is pinned to its default-branch commit on that date, and none was chosen or dropped because of its score.
- **Provenance limits:** license files were identified by name and GitHub's SPDX guess, not read for coverage of the input files. Repository search returns at most 1,000 results per query, so the pool is limited by the query and pages, not by what exists. The saved search, metadata, and tree responses were kept with the batch and not committed, as for the Python and Rust batches.
- **Ground truth:** all 780 findings Evergreen reported on the 122 repositories had their cited line at the pinned commit read and checked against the registry rule they were filed under; no label needed correction. An independent pass over the pinned text (not Evergreen's output) re-derived workflow action references, `setup-node` matrix values, `engines.node`/`volta.node` and `.nvmrc`/`.node-version` pins, declared npm package ranges, container and Compose images, Compose database images, Ruby pins, Go and Python runtimes, Rust toolchain channels, Terraform interpolation-only strings, `TargetFramework`, `targetSdk`, `#Requires -Version`, and Azure `vmImage` labels. It reproduced all 780 findings and raised four possible extras, each explained by a lockfile-resolved version outside the rule even though the declared range allows the end-of-life line. **Precision 1.0 (780/780); recall 1.0 (780/780) on this sample.** Twenty-nine of the 122 repositories have no finding in any detector.
- **Result on the 200-repository Node bucket:** `npm run validate:public-repos -- --ecosystem node` reports 1,130 true positives, 0 false positives, and 0 false negatives, precision 1.0000.
- **Problems found:** none; the review opened no follow-up issue.
