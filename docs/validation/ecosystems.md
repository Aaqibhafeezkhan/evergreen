# Ecosystem corpora

The pinned repository sets and blind selection rules for each ecosystem detector. The summary and the accuracy table are on [Validation](../VALIDATION.md).

## Kubernetes corpus

Thirty-six public repositories at pinned commits cover the `kubernetes` detector. Targeted (chosen knowing their result): `argoproj/argocd-example-apps` (Helm and kustomize applications, including a Chart.yaml dependency on the retired Helm stable repository), `kelseyhightower/ingress-with-static-ip`, `unixhot/salt-kubebin` (a CronJob and three Ingresses), `kubernetes/examples` (two PodSecurityPolicy documents, plus the two end-of-life base images the container detector reports there), and `lusyoe/springboot-k8s-example` (a Helm template and a plain manifest). `ahmetb/kubernetes-network-policy-recipes` is a targeted zero-finding companion (modern NetworkPolicy examples only), added so the kubernetes corpus still has two empty `expected` lists after argocd-example-apps gained the Helm stable finding.

Blind (rule below): `kelseyhightower/kubernetes-cluster-federation` (extensions/v1beta1 Deployments, ReplicaSets, and an Ingress), `motiv-labs/janus` (a PodDisruptionBudget and an Ingress, plus Go and Action findings), `FairwindsOps/pluto` (two extensions/v1beta1 Deployments outside its test directories), `luksa/kubernetes-in-action` (thirty-odd manifests across extensions, apps/v1beta1 and v1beta2, PodSecurityPolicy, CronJob, StatefulSet, CRD, and Ingress), `ossf/package-analysis` (an autoscaling/v2beta2 HorizontalPodAutoscaler), `knrt10/kubernetes-basicLearning` (a networking.k8s.io/v1beta1 Ingress), and five with no Kubernetes finding: `hasura/skor` (the removed version appears only as a `kind: List` item), `stefanprodan/gitops-istio` (the removed version appears only as a Flagger `autoscalerRef`), `doitintl/kube-no-trouble` (the removed versions are in `fixtures/`), `elastic/crd-ref-docs`, and `yaml-schema/yaml-schema`, `shepherd44/helm-charts` (current API versions).

Because the corpus scans every detector, every finding in these repositories is recorded, not only the Kubernetes ones. Each expected finding was checked by reading its line at the pinned commit, and its `groundTruthSource` is a `maintainer-review` note naming the path and line; none of these repositories has a migration commit for the finding, so none is cited. The rules' dates and removal releases come from the Kubernetes migration guide, not from these repositories. A run of `npm run validate:public-repos -- --ecosystem kubernetes` on 2026-10-23 over the seventeen Kubernetes entries reported no false positives or false negatives, with 67 expected `kubernetes` findings, all true.

**Correction (blind ground truth).** The `FairwindsOps/pluto` entry was missing one expected finding: `e2e/tests/assets/list/list-deployment-deprecated-and-non-deprecated.yaml` line 3, an `extensions/v1beta1 Deployment` inside a `kind: List` document. The first corpus run with the `kind: List` parser reported it as unexpected. A re-read of the pinned file confirmed it is a real removed API, so the expected list was extended after that run, and this paragraph records the change. The earlier count of 67 expected `kubernetes` findings predates this correction.

### Scala and sbt blind selection

Blind rule, fixed on 2026-11-07 before Evergreen ran: `gh search code --limit 60` for each of:

1. `scalaVersion := "2.11` `filename:build.sbt`
2. `scalaVersion := "3.0` `filename:build.sbt`

7. Zero-finding queries: `scalaVersion := "2.13`, `scalaVersion := "2.12`, and `scalaVersion := "3.3` `filename:build.sbt`

Walk results in order; skip forks, archives, repositories already in the corpus, and repositories larger than 50,000 KB; keep when the default branch still has the matching file and the file still contains the pin. Pin each at its default-branch HEAD SHA on 2026-11-07. Need enough for stable counts (≥20 repositories with `scala.*` findings, ≥4 zero-finding Scala-ecosystem repositories, ≥⅔ blind, ≥60 `scala.*` expected findings). Prefer multi-module / nested project repositories for finding density. A few known multi-module finding-dense repositories may be added as `targeted` if blind alone cannot reach 60 findings; those are named as targeted in this section after selection.
